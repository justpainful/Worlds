# WorldsAI local runtime scope

On macOS, `ClaudeExecutable` discovers an executable without running it. `ClaudeRunner` starts the selected process without a shell, uses stream-json input/output, disables built-in tools, uses strict MCP configuration, drains stdout and stderr concurrently, limits request and event sizes, serializes runs, and exposes cancellation and a timeout. MCP is absent by default. Supplying an MCP executable also requires an injected host authorizer; the host must verify that this server enforces Worlds account and resource permissions. This module does not provide that server or establish those permissions.

`JSONLineRunAudit` writes only run ID, timestamp and lifecycle state to a caller-selected private file. It does not store prompts, tokens, stderr or model output. This is not equivalent to the existing Worlds `ai_chats`, `ai_messages`, operation history, change aggregation, attachments, session recovery, Keychain token setup, chat references, instructions or tool approval workflow. The host must supply and protect the audit path. CLI system prompts are passed as process arguments, matching the original implementation, and should not contain credentials. Child process descendants are not reliably terminated as a process group, and a descendant holding a pipe open can delay shutdown; this must be addressed before enabling production runs.

Claude Code may not be installed or signed in, and App Sandbox or distribution restrictions may prevent process launch. No real Claude process or user credentials were accessed while implementing this module. On iOS and iPadOS, `ClaudeRunner` returns `unsupportedPlatform`; no compatible remote backend or on-device runtime is implemented. The module is included in SwiftPM but is not linked into the app.

Tests use synthetic scripts for stream-json output, cancellation, and MCP denial, and temporary audit files. Five tests passed on macOS in Actions run 42387357673. The implementation is not functionally equivalent until cancellation under real process trees, authorization, existing conversation persistence and iOS compatibility are addressed.

## Model providers

`AIProviderPresets` is a Swift copy of the non runner presets in `src/ai/providers.json`; `AIProviderPresetSyncTests` fails when they drift. `AIRequests` builds Anthropic Messages requests (`x-api-key`, `anthropic-version: 2023-06-01`, `/v1/models`) and OpenAI compatible chat completions (Bearer key, `/models`, Ollama `/api/tags`), `AISSEParser` and `AIStreamDecoder` turn either dialect's event stream into text deltas, and `AIProviderClient` streams them with `URLSession` async bytes. Errors are `AIProviderError` cases the app localizes. `AIProviderSettingsStore` keeps the chosen provider, address and model in user defaults and the keys in the Keychain (`KeychainAIKeyStore`); `AIKeyValidation` refuses Claude subscription tokens. Keys are never logged or included in error text. The behaviour mirrors the Android `worlds.android.ai` package and the desktop `src-tauri/src/providers`. Tool use mirrors Android: `AIToolWire` builds tool requests for both dialects and reads streamed tool calls, `AIAgent` runs the loop (24 turns, 60 tool calls, one retry without tools when the model refuses them, never for 401, 403 or 429), `AIToolRunner` runs the 10 desktop MCP tools over any `AIWorkspace`, and `AIUndo` puts a reply's changes back. `AIMarkdown` ports Android's Markdown import and export. The app supplies the workspace over RustStore's checked operations.
