# WorldsMathDiagrams scope

The original editor stores mathInline and mathBlock LaTeX in `attrs.latex`, and Mermaid in `attrs.code`. It renders math with KaTeX and diagrams with Mermaid.js strict security mode. This module keeps the original JSON node, ID and unknown attributes while editing only the source string. It has a native SwiftUI source editor, explicit parser errors, and a SwiftMath preview. Mermaid rendering is disabled while compatibility is investigated. The host must provide persistence, undo, authorization and conflict handling.

The native parsers do not guarantee KaTeX or Mermaid.js parity. Mermaid rendering is disabled. `inspectMermaid` uses MermaidKit diagnostics and independently flags some ignored styling and click directives, but an empty diagnostic list never marks fidelity as verified. A successful parse can omit other unsupported statements, so it cannot be treated as evidence of equivalence. Math rendering is limited to SwiftMath's supported math commands and fonts; the upstream project documents limited non-Western glyph coverage. The native preview must not silently replace the original content, which stays intact.

Dependency review on 2026-11-07:

- [SwiftMath 1.7.3](https://github.com/mgriebling/SwiftMath/tree/1.7.3), [MIT license](https://github.com/mgriebling/SwiftMath/blob/1.7.3/LICENSE), release 2025-08-03, non-archived and repository activity through 2026-10-28. The distribution includes separately licensed math fonts; review its `mathFonts.bundle` license files before release. Inspected `MTMathListBuilder.build(fromString:error:)` and `MTMathUILabel` APIs. Upstream describes math-mode scope and font limits.
- [MermaidKit 2.10.2](https://github.com/2389-research/MermaidKit/tree/v2.10.2), [MIT license](https://github.com/2389-research/MermaidKit/blob/v2.10.2/LICENSE), release 2026-10-30, non-archived, relatively new and limited adoption. Its package declares Swift tools 6.2, macOS 14 and iOS 17, and separate MermaidLayout and MermaidRender products. The native parser supports core syntax for many diagram types, not full Mermaid.js syntax. Its optional LinuxRaster trait must not be enabled for Apple builds. Inspected `MermaidParser.parse` and `MermaidView` source at commit `8556a1b80a1f624d35a4c6e13dcb7a5d427f65c3`. A targeted search for URLSession, openURL, WKWebView and process launch in the renderer and layout modules found no matches; this is not a complete security audit.
- GitHub public advisory queries returned no entries on the review date. This does not establish either package is free of vulnerabilities. Dependency pinning, supply-chain review, performance limits and release license notices remain required.

Inputs are limited to 64 KiB but parser CPU, memory, recursion and rendering limits have not been stress-tested. Native views, accessibility, font appearance and error states have not been visually inspected. Corpus tests use actual LaTeX and Mermaid source strings and unknown fields, but have not been run on Apple. This module has not been added to Package.swift or the app.


## Mermaid investigation

The pinned source at [ParseDiagnostics.swift](https://github.com/2389-research/MermaidKit/blob/v2.10.2/Sources/MermaidLayout/ParseDiagnostics.swift) exposes `MermaidParser.diagnose`. It reports some discarded flowchart statements and recognized errors. Its documentation states that, for other diagram types, successful parses return no diagnostics, and deliberately ignored styling and click directives are not reported. [MermaidParser.swift](https://github.com/2389-research/MermaidKit/blob/v2.10.2/Sources/MermaidLayout/MermaidParser.swift) explicitly skips `classDef`, `class`, `style`, `click` and most `linkStyle` effects. The additional regular-expression check catches some directive positions only; it is not a Mermaid grammar and cannot prove completeness.

For a possible native vector path, [MermaidRenderer+SVG.swift](https://github.com/2389-research/MermaidKit/blob/v2.10.2/Sources/MermaidRender/MermaidRenderer%2BSVG.swift) exposes `renderScene`, and [RenderScene.swift](https://github.com/2389-research/MermaidKit/blob/v2.10.2/Sources/MermaidLayout/RenderScene.swift) exposes drawable shapes, polylines and text. This could be consumed by SwiftUI Canvas or CoreGraphics. The display-list primitives do not carry stable source-node identities, so hit testing and round-trip graph editing would require a separate source map and semantic model. Vector rendering does not solve the missing syntax coverage. Before activation, compare parsed content against Mermaid.js using a real corpus and reject every unsupported construct, then verify rendering and edits on Apple devices. The module remains isolated from the app.
