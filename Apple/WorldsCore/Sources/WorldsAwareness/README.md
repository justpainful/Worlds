# Yjs awareness: isolated state engine

The original `src/sync/session.ts` binds awareness to the content Y.Doc and sets `user` (id, name and color). `src/sync/extensions.ts` passes the same awareness instance to Tiptap CollaborationCaret. Cursor anchors are Yjs relative positions, not stable text offsets. `src/sync/provider.ts` broadcasts updates, transmits local state on reconnect, and removes remote states when the connection closes. The service overrides user.id with the authenticated account, verifies client ID ownership across sockets, and validates drawing presence (`services/sync/src/doc.ts`).

This isolated state engine uses `WorldsSyncWire` framing and Yjs clock acceptance rules, retains tombstone clocks, rejects malformed JSON, handles local reassertion, heartbeat and remote expiry. The caller must set initial `{}` at clock zero, then its user state, keep its client ID identical to the Y.Doc client ID, call tick regularly, send returned updates, query the server, and reconnect correctly. It deliberately has no network, editor, cursor mapping, drawing validation, permissions, UI or timer integration; it is not enabled in the app or Package.swift. User IDs in incoming states are only authoritative when received from the authenticated service. Avoid persisting ephemeral awareness.

The test fixture was emitted by the repository's actual Yjs and y-protocols, but Swift tests have not been run on an Apple SDK. More work is required for XML editor bindings, resolving Yjs RelativePosition through the same yrs document and current editor layout, selections after edits and multiple text blocks, correct lifecycle and disconnect semantics, clocks across reconnect, service integration, and live two-client validation. Never interpret Yjs positions as UTF-16 indices without resolving them through the shared document. Cross-client collisions and untrusted/malformed states require review before activation. Swift test input is synthetic and uses no user data.
