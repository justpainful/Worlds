# Conversation interface boundary

This standalone SwiftUI view requires an injected authorized `ConversationService`; it has no built-in demo, fake messages, process runner or product entry point. It loads stored messages, shows streamed text and supplied tool statuses, keeps drafts until the service explicitly confirms acceptance, offers cancellation, and reloads after a run. Errors are visible. Tests use only an isolated synthetic service; they have not run on Apple.

The current Claude runner and its coordinator do not yet implement this interface. In particular, a future adapter must guarantee a durable user-message acceptance event, map deltas without duplication, serialize runs, handle cancellation and preserve actual stored messages and tool activity. A reload failure must retain streamed output, as the view model does. Scope does not include conversation list, markdown, attachments, mention chips, model controls, tool approval, undo, per-chat draft persistence or iOS runtime. Cancel requests do not guarantee the process tree was terminated. This module does not authorize data or tools. It is included as an experimental Swift package target but is not wired to the app. No end-to-end, accessibility, Dynamic Type, RTL or visual review has been performed.
