# Personal stroke operation session

This isolated actor connects the original-schema `StrokeOperationBuilder` to `PersonalDrawingWriter`. A caller supplies an already authorized local database, the identity used as the operation actor, the revision displayed during input, the target frame and layer, and actual pointer samples. The actor reloads the drawing and checks the expected revision, frame and every layer ancestor. It rejects locked layers, erasing an alpha-locked layer, cyclic or missing ancestors and asset brush tips, and propagates the effective alpha-lock bit to the generated operation. The existing Rust drawing facade remains authoritative for personal access, synchronization restrictions, scene validation, revision conflicts and its refusal of asset-backed history. No user-facing canvas or product action uses this module.

One operation is held until a response arrives. If an apply error has an uncertain outcome, `retryPending` resubmits exactly the same operation ID and payload, so the original idempotency handling can distinguish a retry. The caller must not start a new stroke in that session until the pending operation has been resolved; a persistent rejection requires leaving the session and recovering or reopening explicitly. This actor does not establish account ownership, grant workspace access, retain a security scope for its host, or verify database file identity across calls. It must not be connected to a user's original database until those responsibilities and Apple integration are verified.

Isolated tests exercise writing a synthetic stroke and reloading it, stale revision rejection, a locked layer and an invalid frame. Tests have not run on Apple and do not establish real pointer capture, all brush styles, complete layer semantics, rendering parity, animations, collaboration, image assets, undo/redo, or safe asset copying. The exact visual comparison work is separate; no approximate renderer is enabled by this module.
