# Presentation persistence boundary

The experimental bridge uses the Rust SQLite transaction to read personal presentation blocks and save against the complete ordered baseline, metadata and revision. Non-slide blocks remain intact; shared pages, inaccessible attachment owners, remapped IDs and conflicts are rejected. A failed or uncertain save invalidates the session and requires a new read. The Swift wrapper is not connected to application UI and is not in Package.swift. The source is ready for Apple build review, not proven correct on Apple. The integration test uses only a copied synthetic v11 database. Loading/saving media bytes, live collaboration, permissions for shared workspaces, full history parity and exports remain unimplemented. The caller must hold appropriate database security-scoped access across the whole workflow and must not enable UI writes before Apple integration tests and further security review.
