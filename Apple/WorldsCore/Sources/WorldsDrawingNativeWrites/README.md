# Experimental personal drawing writer

This bridge calls the same `drawing_persistence` implementation used by Windows for loading and applying operations, including scene validation, revision checks, idempotent operation identifiers, journal updates, indexing, links and history, within an immediate SQLite transaction. The original scene and annotation validation source is shared as well. This is not a separate approximation of the operation engine.

The Apple facade rejects shared or deleted pages, pages with sync bindings, version-restore receipts, library publications and every scene containing assets. Asset-backed writes are disabled even when the original is present. On Unix a prospective reader traverses from a directory descriptor with `openat` and `O_NOFOLLOW` for every component, checks page ownership and file size, and holds an open descriptor during validation. This reduces symlink traversal risks but does not guarantee that a stored path still names that file after the descriptor is opened; another process can rename, replace, or modify it before or after the SQLite commit. SQLite and the filesystem do not supply a combined atomic transaction here. On Windows the prospective reader fails closed. The original Windows application is unchanged. Do not enable asset-backed writes until the file ownership model and coordinated storage solve these races; the experimental bridge remains disconnected from the app.

This does not implement drawing sync, portable package export, import, snapshots or restore. A drawing with an unsupported dependency is refused rather than saved with it missing. Original user data must not be edited through this API until Apple tests, integration and security review pass. It is not connected to the app.

Rust fixture tests cover personal save, reload, idempotent retry, stale revision, SQL fault rollback and a page becoming shared. Existing Windows drawing tests exercise the shared implementation. Swift fixture tests have not run on Apple. The FFI request size cap is 8 MiB and the response is a JSON envelope. A failure can be an uncertain outcome if the process loses the response after commit; retry the same operation ID, as the original store supports.

Isolated Rust tests cover rejecting asset-backed writes, missing files, wrong owners, traversal, rollback and a sync binding. Unix-only tests cover symlink traversal and demonstrate path replacement after opening. A Unix-only symlink test is available for CI; it has not run on Windows.
