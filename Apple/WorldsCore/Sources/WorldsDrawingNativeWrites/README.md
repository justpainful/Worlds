# Experimental personal drawing writer

This bridge calls the same `drawing_persistence` implementation used by Windows for loading and applying operations, including scene validation, revision checks, idempotent operation identifiers, journal updates, indexing, links and history, within an immediate SQLite transaction. The original scene and annotation validation source is shared as well. This is not a separate approximation of the operation engine.

The Apple facade rejects shared or deleted pages, pages with sync bindings, version-restore receipts and library publications. It accepts only assets owned by the drawing itself, with normal relative paths in the database-adjacent attachments folder, no symlink in checked ancestors, a regular file, and a file size matching its database row. It does not implement drawing sync, portable package export, import, snapshots or restore. A drawing with an unsupported dependency is refused rather than saved with it missing. Path and file checks are not atomic against a same-user process replacing files between validation and transaction commit; equal size does not verify content integrity. These checks do not constitute a security boundary and require Apple filesystem review. Original user data must not be edited through this API until Apple tests, integration and security review pass. It is not connected to the app.

Rust fixture tests cover personal save, reload, idempotent retry, stale revision, SQL fault rollback and a page becoming shared. Existing Windows drawing tests exercise the shared implementation. Swift fixture tests have not run on Apple. The FFI request size cap is 8 MiB and the response is a JSON envelope. A failure can be an uncertain outcome if the process loses the response after commit; retry the same operation ID, as the original store supports.

Isolated Rust tests cover an owned original, missing file, wrong owner, traversal, rollback and rejection of a sync binding. A Unix-only symlink test is available for CI; it has not run on Windows.
