# WorldsDrawing scope

This module reads and re-encodes a schema 1 scene as open JSON, retaining fields it does not understand. It checks basic container structure and schema version only. It does not implement the full validation rules in `src/drawing/model.ts`; do not write the result into a user's original data store based on these checks alone. The drawing document envelope and its operation journal are retained as opaque JSON, but the document parser does not itself validate or replay operations. The separate experimental DrawingJournal can replay the subset described below. The module does not handle migrations, undo, shared synchronization, assets or attachment ownership.

`DrawingRenderer` is an experimental CoreGraphics preview that follows `src/drawing/renderer.ts`. It composites nested layer groups recursively (a group's own elements, then its child layers, then the group's opacity and blend), draws every desktop shape type (including editable paths, point lists, anchored arrows, gradients, dashes and the numbered marker) with missing paint fields defaulted to `DEFAULT_PAINT`, paints every desktop brush kind from the source dabs with the per kind pigment rules (crayon and natural pencil granules, oil bristles, watercolor wash and rim, soft edges, spray particles) and draws marker and highlighter strokes as uniform vector strokes. Eraser strokes use destination-out and alpha-locked elements use source-atop inside their own layer. Element masks use the mask alpha (base rectangle, reveal and hide strokes, inversion) in linked or world space. Brightness, contrast, saturation, grayscale, invert and blur are applied as CSS filter equivalents, optionally limited by an adjustment mask. Temperature, sharpen and pixelate have no vector equivalent on the desktop either and are skipped with a reported issue. Redactions are painted last as opaque black rectangles. Images, references, raster elements, mask images and textured brush tips are not loaded, and text uses a simplified CoreText layout. Every approximate or unsupported visible element is reported, and the preview is always marked non-exact and cannot be treated as an authoritative export. Pixel behaviour is covered by synthetic XCTest scenes in `DrawingCompositingTests`; it has not been compared against desktop renders on a device.

The initial scene tests passed on macOS in Actions run 42387357673. Later tool and journal tests are not yet verified. The module is included in SwiftPM but is not connected to the app.


## Experimental input helpers

`DrawingTools.swift` builds schema-shaped stroke edit operations for the source brush kinds, including textured brush settings, as well as eraser strokes. It retains pressure, tilt, time, color and alpha-lock metadata and translates samples into node-local coordinates. Inputs outside its supported ranges are refused. It does not render pressure, reproduce original textured brush rasterization, validate layer or frame ownership, apply edits, validate the complete scene or save to storage. The generated operation must not be applied to user data until it passes the original store's validation and integration tests. Unknown brush kinds are rejected explicitly. Texture and tip assets are retained as metadata; textured rasterization is not implemented.

`LaserOverlay` is in-memory session data only, with color, lifetime and linear fade. It is not connected to rendering or collaboration. `ShapeRecognition` implements line, rectangle, ellipse, triangle and right triangle recognition with the source thresholds. `ShapeCorrection` turns a recognized brush stroke into the desktop's corrected node (the patch `Stage.tsx` and `DrawingView.tsx` commit as a second "Correct hand-drawn shape" edit), and `ShapeCorrectionOperationBuilder` wraps it as that edit, so undoing it restores the stroke. The contour algorithm has not been tested against all source inputs and does not provide complete recognition parity.

The `recognition-source-corpus.json` fixture is generated by `Apple/scripts/generate-shape-corpus.cjs` from the original local checkout, including its uncommitted recognition and geometry changes. The inputs are synthetic approximations, not recorded pen strokes. Source SHA-256 values at generation were `360eb92fb87514aa6914ed31ab07d6ad5796106e1b48df6f47d1c752f3542506` for `recognition.ts` and `211263ce6f23b914e04df255af79223f0b84278ab0aef3ec603957676e1f4bb8` for `geometry.ts`. The corpus covers 12 line, rectangle, rotated square, triangle, ellipse, long-stroke and rejection cases; Apple execution is required before claiming these comparisons pass. Native code rejects non-finite input; source behavior on invalid floating-point points is not claimed as identical.

`DrawingToolsTests` includes a stroke JSON fixture generated from the original `newNode`, `strokeBounds`, and `putNode` code, plus source-generated recognition and pressure fixtures, and checks for metadata and laser. These XCTest cases and fixture comparisons have not run on Apple. SwiftPM includes the three fixtures as test resources. No editing UI or export was enabled.

The CoreGraphics preview paints strokes from `StrokeDabEngine` dabs, so pressure, taper, dab spacing and the seeded pigment noise follow the source. It is not a pixel match: it does not reproduce the desktop 512 pixel tile rasterizer, level of detail or subpixel snapping, and it remains marked non-exact. Brush tip asset rendering remains unsupported.



## Experimental journal and selection

`DrawingJournal` applies put, remove, patch, ordering and default-frame edits to an in-memory schema 1 document. It checks revisions, operation IDs and authors for toggles, supports frontend-style per-author undo/redo target selection, and replays toggles from the seed rather than overwriting another author with a flattened snapshot. It preserves unknown envelope fields and exposes the existing JSON document round trip. It performs structural checks only, not the full `validateScene`, native SQLite permissions, asset ownership, pixel guards, version restore receipts, journal size, or synchronization authority. Guarded and unknown new operations are rejected rather than simplified. This must not be used to mutate or export user projects until the original validation and persistence path is integrated.

`DrawingSelection` resolves explicit IDs in scene order and prepares basic transform patch values. It is not a geometric selector or handle UI, and it does not implement mask, anchored reference, text, group, layer hierarchy, snapshot and special transform semantics. `DrawingDocument.json()` writes the document JSON envelope, not the original portable project package. Original packages can include assets, versions and metadata; package import/export and visual export are still missing. Do not name or advertise this JSON as a full project export.

`original-journal-fixture.json` was generated with the original TypeScript `newDrawing`, `edit`, `appendOperation`, `historyToggle`, and `putNode`. The XCTest compares add, move, undo, redo and JSON round trips against that fixture and checks selected invalid requests. The fixture is included in SwiftPM; these tests have not run on an Apple SDK.

## Dab geometry candidate

`StrokeDabEngine` ports the source dab spacing, interpolation, pressure, taper, seeded xorshift noise and spray particle positions, including a conservative work budget. The fixture `original-dabs-fixture.json` was generated by calling the actual TypeScript `strokeDabs` with hard and spray brushes and records full dab outputs. XCTest compares numeric fields with a tolerance; the tests have not yet run on an Apple SDK. No raster output, layer compositing, highlighter appearance, stroke saving, text or laser rendering is supplied by this engine. It must not be called pixel parity or connected to saving until integration and visual comparisons succeed. SwiftPM must explicitly include this fixture as a test resource.

## Isolated raster candidate

`StrokeRasterCandidate` paints hard-edged hard, ink and pencil dabs and uniform highlighter strokes into a caller-supplied CoreGraphics context. A single transparency layer prevents stroke-opacity accumulation for overlapping highlighter segments. Pressure-sensitive highlighter shapes, taper, straight-line mode, soft brushes, textured tips, erasing and effects are rejected rather than approximated. This is not connected to the scene renderer, storage or app. The two synthetic pixel tests check basic compositing and rejection, not equality to the original browser canvas. No original-rendered image fixtures or Apple execution and visual comparison have yet been produced; antialiasing, alpha, color space, transforms and multi-layer composition remain unverified. Do not describe this implementation as visually equivalent.

The experimental raster path now paints non-highlighter dabs into a source-resolution 512-pixel tile before low-quality interpolation, reflecting the original rendering order. It rejects strokes crossing a tile boundary because source halo and seam handling are not implemented. This hypothesis was motivated by 4x comparisons; it has not yet been tested against the source images on Apple, and no improvement or equivalence is claimed. The highlighter remains on a separate direct uniform path.
