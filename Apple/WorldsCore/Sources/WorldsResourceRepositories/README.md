# Experimental resource repository bridge

This module adapts WorldsProjects and WorldsGallery to NativePersonalStore and RustStore. It is not connected to the application. Rust reads and writes project metadata and gallery blocks only for personal pages, checks the complete expected metadata and ordered block contents inside an immediate transaction, verifies both original and resulting gallery attachment owners, preserves unknown non-gallery blocks, and delegates to the original `store::set_page_meta` and `store::save_blocks`. Removing a gallery item does not delete an attachment. The original store controls its own history, index and change records; it does not record a separate history entry for every metadata change.

Workspace authorization and collaboration are not implemented. Pages or referenced attachments whose owner is shared, missing, deleted, or unestablished are refused. This is intentionally more restrictive than Worlds on Windows. Projects and galleries that reference inaccessible or deleted resources may therefore be unavailable in this experimental bridge. Project creation, resource moves, gallery import, attachment file creation, external sharing and complete feature parity remain unfinished. The existing RustStore attachment-directory function is a disabled stub; do not point it at user data or claim import support. A real importer needs a security-scoped source and authorized vault root, bounded format validation, private staging, atomic DB integration, crash recovery and orphan cleanup, plus real platform tests.

The integration tests use a synthetic schema-v11 fixture and exercise the Swift bridge and original Rust store. They have not yet run on Apple. Rust unit tests run separately; passing them does not prove the Swift bridge, device file access, security scope or UI is safe. The host must not expose these writes until Apple CI, permissions, recovery and end-to-end interaction checks pass.

The experimental `readStream` and `saveStream` operations operate only on personal stream pages. A save compares both the full metadata baseline and revision inside a transaction, retains unknown metadata and stream fields, and delegates the update and indexing to the original store. URL validation requires HTTP or HTTPS, and format detection follows the original `.m3u8`, `.m3u`, and `.mpd` rules. This does not implement shared-page permissions, validate stream availability, guarantee AVFoundation playback, or prove the identity of a pathname-backed database against same-user replacement. Swift integration has not yet been verified on Apple.

The experimental `readSpreadsheet` and `saveSpreadsheet` operations operate only on personal spreadsheet pages. A save sends the complete metadata baseline and revision; Rust compares both inside a transaction, requires every metadata key other than `sheet` to be unchanged, checks the workbook shape the desktop reads (non-empty `sheets` with unique string ids, object cells whose `v` is text, and a valid `activeSheetId`), and delegates to the original `store::set_page_meta("sheet")`. Unknown workbook, sheet and cell fields pass through untouched. The Rust tests for it run with `cargo test` and are not part of CI; the Swift path has not been exercised on a device.
