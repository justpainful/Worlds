# Isolated drawing harness

This iOS/iPadOS-only experiment copies the synthetic Worlds v11 fixture into a unique temporary directory. It never opens a user database and is not included in the product. The host displays only scenes accepted by `ExperimentalStrokeSceneRenderer`, then captures touch or Pencil samples and saves original-format stroke operations with `PersonalStrokeSession`. It reopens from SQLite. Input is limited to a small region to avoid unsupported raster tile cases. The view intentionally retains an unconfirmed stroke rather than allowing further edits after an error.

Supported brush configurations are restricted to hard, ink, pencil and highlighter, with selected color and width saved in the original stroke. A separate local laser overlay captures live touch/Pencil points, supports color, width and 200–4000 ms fade, and is not persisted or sent to collaborators. There is no live stroke preview, eraser, selection, assets, multiple-frame navigation, layer editing or export. Pencil estimated properties that remain unresolved are rejected. The current capture surface is UIKit only. No device, visual, or UI verification is implied until Apple CI runs. No product toggle is supplied.

Right-triangle recognition is available as an opt-in experiment for the hard brush. It first saves the stroke, then applies a separate source-shaped correction patch with originalSamples and points. If the correction is rejected, the original stroke remains. If the response is lost, its result is uncertain; in either case the harness stops further input. Other recognized shapes stay as strokes. The limited renderer must be explicitly opted into right-triangle display. Canvas comparison and isolated SQLite tests require an Apple CI run; this is not a claim of parity or a product feature.

The UI test named `testSyntheticTriangleCorrectionAndReopen` explicitly injects a sequence of synthetic touch samples through the same capture, controller and writer path, then screenshots after save and reopen. It is not a hand-drawn gesture or Pencil device test. XCTest public drag APIs provide a start and end for a drag, not a continuous multi-turn path; `testDrawSaveAndReopen` separately exercises an actual UI drag.

The UI tests exercise a real simulator drag for the blue highlighter, reopening and checking its stored kind and color, and a separate simulator laser drag that checks its fade and unchanged drawing revision. These tests have not yet run on Apple and do not verify a physical Pencil, collaboration or parity for unsupported brushes.

The editor implementation is shared with the DEBUG-only local-copy drawing sheet. The sheet reads the existing single profile as the actor, refuses unsupported scenes, and verifies the opened database identity before and after calls. This is detection of ordinary replacement within the app container, not an atomic defense against a same-user swap-and-restore. Writes remain personal-only through Rust and refuse asset-backed histories. An experimental AppKit path captures mouse and tablet-point input on macOS; pressure is mapped from AppKit’s normalized pressure. Tablet tilt and platform-specific pressure-event streams are not translated, and this has not been checked with a physical tablet. The macOS sheet remains DEBUG-only.

A pending stroke is retained in memory until exact-operation retry succeeds or the user explicitly discards an input that was never submitted. Closing while a submitted stroke remains unconfirmed requires explicit warning that the retained recovery data will be lost and the operation may have succeeded. A failed shape correction triggers a fresh read; when the scene cannot be verified, further drawing is blocked. Process termination still loses an in-memory pending stroke. No test-only synthetic control is compiled into the local-copy sheet. Apple builds, visual review and physical Pencil validation remain outstanding.

The macOS capture cancels an active gesture when its view leaves a window, the window resigns key status, or `cancelOperation` is called. A cancelled gesture returns its in-memory samples to the host and is not submitted. Its unit test uses a synthetic NSEvent and cannot establish real tablet behavior. AppKit event semantics: [tablet point](https://developer.apple.com/documentation/appkit/nsevent/eventtype/tabletpoint), [pressure](https://developer.apple.com/documentation/appkit/nsevent/pressure).
