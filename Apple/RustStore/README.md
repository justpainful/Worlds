# Worlds personal store experiment

This Rust library includes the repository's existing `store` and `content` modules by path. It exposes personal-page creation, rename, trash and whole-block-list save through a C ABI. Each write uses an immediate SQLite transaction and calls the original store. Existing databases are opened without creation or migration, and only schema version 11 is accepted. Shared, deleted and explicitly shared metadata pages are rejected. Trashing a subtree checks every descendant first. Saving blocks is restricted to pages and documents. `create_version_checked` keeps a page or document as a named version after comparing its revision, and `restore_version_checked` restores one with the original restore (which keeps the current state as a version first), refusing a version of another page and any block with properties; the assistant uses them to undo a reply.

The Apple app uses it, through `WorldsNativeWrites`, to write the person's own workspace database in place (after `WorkspaceWritePreflight` in `WorldsWorkspaceAccess` accepted its location) or an independent local copy. Native writes record the change origin `native` so the desktop's change watcher merges them, a new page that would join the active team workspace is refused, and metadata saves keep the earlier state as a version. Device behavior has not been checked. Authentication, shared collaboration, sync, file-provider coordinated access, authorization, restore, permanent deletion, attachment operations, rich resource CRUD, search API and full parity are unfinished. Drawing and account dependencies in this crate fail closed and are not functional. The request must be made on a background executor. The API returns allocated JSON and its caller must free it exactly once using `worlds_store_free`. File access authorization and security-scoped URL lifetime belong to the native host.

The v11 fixture in `tests/fixtures/worlds-v11.db` contains synthetic data only and was generated by applying the eleven SQL migrations from `src-tauri/src/db.rs` and `src-tauri/src/sync/mod.rs` in order. An earlier local test temporarily used a v1 fixture with a manually changed version; it did not validate the real v11 schema. Current tests use the migration-created v11 fixture. They do not establish migration safety, all store behavior, actual user data compatibility or Apple compatibility.

`cargo test --offline` succeeded on Windows for nine tests, including two inherited from the source content module. Build output lives under `target/`, which is ignored. No test result should be interpreted as permission to enable writes in the UI.


## Apple build and Swift bridge

Run `bash Apple/RustStore/scripts/build-apple.sh` on a Mac with Xcode and Rust installed. It builds iOS device, Apple Silicon and Intel simulator, and Apple Silicon and Intel macOS static slices, then creates `Apple/WorldsCore/Artifacts/WorldsRustStore.xcframework`. The artifact is ignored by Git and must be rebuilt in CI before package resolution. Set `WORLDS_REQUIRE_NATIVE_WRITES=1` in jobs that require the bridge so a missing artifact fails package resolution. Without the artifact, the package exposes read-only targets and has no native write product.

The experimental `WorldsNativeWrites` target manages the security-scoped URL for the duration of a call, releases every FFI response, and reports stale revisions as conflicts. It does not coordinate an iCloud file provider, so the app keeps databases in iCloud Drive and other File Provider or network locations read only, and it does not acquire authorization for shared workspaces, which RustStore refuses. Device verification is still pending.

`WorldsNativeWritesTests` uses an isolated synthetic fixture. It checks FFI writes and conflicts, the Rust and Swift SQLite versions, the Rust FTS5 compile option, and a Swift SQLite MATCH query after a Rust write. A matching version is a useful check, not proof that all link or ABI conflicts are absent. These Apple tests and the XCFramework script have not been run in the Windows environment.
