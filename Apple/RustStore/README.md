# Worlds personal store experiment

This Rust library includes the repository's existing `store` and `content` modules by path. It exposes personal-page creation, rename, trash and whole-block-list save through a C ABI. Each write uses an immediate SQLite transaction and calls the original store. Existing databases are opened without creation or migration, and only schema version 11 is accepted. Shared, deleted and explicitly shared metadata pages are rejected. Trashing a subtree checks every descendant first. Saving blocks is restricted to pages and documents.

This is not yet approved for use by the Apple app. It is not linked to Swift, and neither Apple compilation nor device behavior has been checked. Authentication, shared collaboration, sync, file-provider coordinated access, authorization, restore, permanent deletion, attachment operations, rich resource CRUD, search API and full parity are unfinished. Drawing and account dependencies in this crate fail closed and are not functional. The request must be made on a background executor. The API returns allocated JSON and its caller must free it exactly once using `worlds_store_free`. File access authorization and security-scoped URL lifetime belong to the native host.

The v11 fixture in `tests/fixtures/worlds-v11.db` contains synthetic data only and was generated by applying the eleven SQL migrations from `src-tauri/src/db.rs` and `src-tauri/src/sync/mod.rs` in order. An earlier local test temporarily used a v1 fixture with a manually changed version; it did not validate the real v11 schema. Current tests use the migration-created v11 fixture. They do not establish migration safety, all store behavior, actual user data compatibility or Apple compatibility.

`cargo test --offline` succeeded on Windows for nine tests, including two inherited from the source content module. Build output lives under `target/`, which is ignored. No test result should be interpreted as permission to enable writes in the UI.
