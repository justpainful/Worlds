# Android identity foundation

`Android/core/identity` implements the existing email challenge, device-bound session, signed refresh and logout contracts from `docs/contracts/identity.md`. The Android app exposes email sign-in, session refresh and server-confirmed sign-out through an Account screen. It lists and creates server workspaces and connects shared pages to the account-scoped sync runtime. No production endpoint is configured.

The client registers a fresh Ed25519 device key, stores its software private seed and tokens in one AES-GCM authenticated record in the app no-backup directory, and protects the encryption key with Android Keystore. Bouncy Castle supplies Ed25519 on the supported API 26 baseline. HTTPS is mandatory in the production transport, redirects are disabled and requests are never automatically retried.

Refresh tokens are single use. A process-wide lock serializes refreshes and the encrypted record is marked in flight before the request. When Android reports no available network, refresh stops before marking or sending the token so the stored account remains available for offline work. If a request is sent and the response is lost, validation fails, or persistence fails, the record remains quarantined. It cannot be refreshed or returned as an active session after restart; the user must sign in again. A network can be present but unable to reach the server, so the preflight cannot eliminate uncertain refreshes. Session records are bound to their identity server URL. Signing out clears local state only after the service confirms revocation.

`Android/tools/test-network-availability.ps1` tests Android's reported network state on an emulator with Wi-Fi and mobile data enabled and disabled, then restores their initial settings. In each state it uses an encrypted test session and a fake identity transport to check whether refresh is sent and whether the session remains readable. Identity instrumentation tests separately exercise the same preflight and uncertain-response handling. Physical-device and production identity behavior have not been verified.

Android instrumentation tests cover encrypted persistence, a signed refresh, sequential concurrent refreshes, interrupted refresh recovery, server binding, and logout with a fake transport. A separate opt-in local Worker test uses a test-only cleartext loopback transport over adb reverse. On Android 15 it verified a synthetic email challenge, device-bound sign-in, signed refresh, `/me`, logout, workspace creation and listing, and rejection of the revoked device against the actual local `services/identity` Worker. This does not test the production HTTPS path, API 26 hardware, process death during disk writes, passkeys, production delivery, production account interaction or sync. The account and workspace UI is exercised with a fake gateway; the production HTTPS path has not been tested end to end with the UI. The local Worker and data were not deployed.
