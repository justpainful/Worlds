# Android feature parity audit

This is an initial source inventory, not a complete parity matrix. Source
presence is not evidence that a feature works. Android implementation and
verification remain partial. The primary desktop checkout has additional
uncommitted drawing work which is not included in this branch.

| AI | `src/ai`, `src-tauri/src/ai.rs` | Partial: the assistant streams real replies from Anthropic, OpenAI compatible providers (OpenAI, Gemini, Groq, DeepSeek, Mistral, xAI, OpenRouter, custom) and local servers (Ollama, LM Studio), with the API key encrypted by a key in the Android Keystore (`worlds.android.ai.AiClient`, `AiProviders.kt`, `AiProviderStore.kt`). Shared page Markdown export, copy and sharing are available for authorized online
and cached offline pages. They project the captured saved blocks through the same
Markdown converter as personal pages. The result excludes the unavailable shared
page title, an open draft and original attachment bytes, and unsupported content
can be omitted. Android 11 and 15 emulator tests verify output, picker cancellation,
offline edits, account changes and write failure. Android 15 also saved and read
the actual file through the system picker and opened the Android sharesheet. Other
document providers and delivery to an external sharing target remain unverified.
An Android 11 emulator previously stalled while laying out over 100,000 characters
in one shared text field. The editor now displays up to 4,000 UTF-16 units per
part, with previous, next and numbered navigation while retaining the complete
draft for saving. Synthetic Android 11 and 15 emulator tests pasted, navigated,
edited, saved and reopened a 100,000-character paragraph without the earlier
stall. They verified the full saved Yjs text, including emoji, and a mock peer
received both creation and an edit. Selecting text across part boundaries is not
supported. Production sync for this long-text case, larger documents, hardware
performance and other input methods remain unverified.

Working draft backups coalesce consecutive pending changes for the same draft,
so a slow disk does not retain every intermediate long-text copy in the write
queue. Cancel and successful save retain an ordered removal barrier, while screen
close or account change lets the latest accepted write finish under the original
account. Android 11 and 15 emulator recovery tests cover rapid updates, account
changes, cancellation, stale failure reports and write errors. A sudden process
termination can still occur before an in-flight backup reaches storage.

Each area requires further inspection of behavior, persistence, contracts,
tests and source status before it can be expanded into feature-level rows.
