# Shared library and palette publications

Each immutable drawing version may carry a `libraryPublication` descriptor with schema1, item ID, publication number, name, category, tags, original source ID, payload and timestamp. The payload is limited to64KiB and the publication history to500 versions, within the existing64MiB dependency directory limit. No artwork or large library object is stored in page metadata; its `drawingLibrary` flag is only for discovery.

Versions and owned originals use the existing drawing dependency channel. Originals arrive and pass integrity/ownership checks before the native checkpoint installs their references. The native checkpoint atomically rebuilds library items/version mappings from validated descriptors. A repeated checkpoint is idempotent; older directories cannot roll back names, tags or the current version. Publication number, saved-version ID, category, content and timestamp cannot be reused inconsistently. Missing publication history is refused. Legacy publications gain new descriptor-bearing snapshot IDs without rewriting the old snapshots.

The Worker binds every descriptor to its actual document ID and saved-version revision/timestamp, enforces complete unique publication history before committing, and attributes a new publication to the authenticated actor. Descriptor fields cannot claim owner, scope or workspace. Owner display uses the actual account/version author; scope and access always come from the page/workspace/account tables. Local/native checks repeat the binding and immutable-version checks. Source rights and item rights remain independent.

New workspace publications are siblings of their original drawing, in its folder/workspace, so deleting or revoking the original drawing does not implicitly delete the published copy. Publishing requires actual edit access in the destination. An authorized update can detach a legacy source-child publication into its source folder when the publisher has destination rights. Read-only migration never moves a legacy page or broadens its access. The source state is available/missing/denied, while owned published content remains usable under its own rights. Inserted copies retain independent originals and do not change when the publication updates or disappears.

Library discovery scans current drawing page metadata with concurrency2, refreshes publication resources through the existing manager and retains no pane lifetime. Page/version updates refresh the permission-filtered list. A missing or revoked item closes its preview. Actual preview asset loading waits for a current successful item-access check; a failed/revoked check unmounts the renderer and cancels its resources. Linked inserted copies show source unavailable and can detach without losing their artwork.

The item modal shows selected-version name/tags, owner, scope/version history, source state and local/sync status. Required text fonts are checked locally. Missing fonts require an explicit fallback choice before insertion/template use. Font names are retained, font files are not embedded, and the UI asks the owner to check the license for editable sharing. Missing owned originals surface as real preview/import errors rather than placeholder content.

The service advertises `capabilities.libraryPublications:1` alongside `pixelSourceGuards:2`, including missing-state errors. A new client retains outgoing publications locally and refuses incoming publication checkpoints before original downloads/native storage when that capability is absent. It also validates the directory binding before download. Ordinary drawing and flat pixel-guard behavior remain unchanged. Deployment of the updated service remains a separate action.

Evidence: [native-library-sync.json](qa/native-library-sync.json). It combines10 real Rust/SQLite/Worker/production-transport checks,5 Rust library tests,10 root library/manager tests and the50-test service suite. Corruption, duplicate/missing history, stale writes, native reopen, source deletion, independent owned originals, access revocation and legacy protocol refusal are exercised. General workspace page-tree import is a fixture boundary, and native visual/physical acceptance is separate.

Discovery caches each inspected drawing ID/modified timestamp, so ordinary brush edits do not refetch every publication. Every publication advances its small page-tree modified revision, including color/tag-only edits. Manual refresh clears the discovery cache. Missing fonts can be checked again after installation. Style payloads are limited to paint/textStyle and cannot inject geometry, attachment or ownership fields.
