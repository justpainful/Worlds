# Worlds Drawing: locked design decisions

## Screen annotation decision

Screen annotation holds a user-requested still capture beneath the actual drawing stage. The capture fills the display; a compact dark neutral toolbar uses the existing panel, text, accent and type roles above. Controls expose actual drawing actions, color, size and laser duration, plus saving to the current drawing and exiting. The image is local memory until the user chooses to save it. The still image does not control playback in the captured application.

## Frozen screen drawing, 2026-11-06

The screen mode captures the active monitor locally and presents that still image as the drawing surface, with a compact top tool strip based on the owner's reference. The strip uses the existing drawing tools and their actual colors, widths, laser and text controls. It keeps the lesson visible under the artwork, uses the existing neutral panel #1C1C1E and foreground #F5F5F7 with the current accent, and uses Instrument Sans, IBM Plex Sans Arabic and IBM Plex Mono as defined below. It does not tint the captured image. Saving or copying is explicit, and leaving restores the previous Worlds window. A still capture does not pause the underlying video; the interface must say this rather than implying that the source application is paused. Screen pixels stay local and are not transmitted or persisted without an explicit save.

## Annotation inspector decision, 2026-11-06

The annotation inspector explains actual artwork with an independently movable text label, a connector and a normalized anchor on an existing element. It stays inside the existing inspector, using the six palette roles and Instrument Sans / IBM Plex Sans Arabic / IBM Plex Mono sizes defined below. A small edge-position selector represents the target's actual local rectangle; image rotation and reflection are resolved in document geometry, never by mirroring UI. Source review is a text list naming missing targets, changed originals and crops, with explicit repair or detach actions. Status and reusable appearance presets use compact native selects and existing neutral buttons. Presets change appearance only; they never copy target IDs, task links or label content. Apply is one fenced, stale-checked journal edit with Undo; cancel saves nothing. No new materials, decoration, animation or character assets are introduced.

Status: implementation brief, 2026-11-05. Scope: the drawing editor agreed in this chat, including all eight workspace features. This file governs new drawing UI; existing Worlds components remain authoritative for the shell.

## Subject

A drawing resource inside Worlds for drawing, editing photographs, annotating problems, and turning an annotated region into a linked workspace task.

## Vernacular

Actual working material: brush tip, stroke, pigment, transparent pixels, raster tile, image original, mask, frame edge, layer stack, annotation anchor, task link, revision, experiment and presentation step. The canvas and its frame edges are the organizing structure. The layer stack is an ordered list, never a set of decorative feature cards.

## Palette

Use existing Worlds tokens, including their light-mode values and user accent overrides. Dark base values: working surround #242426 (neutral backing that does not tint images); panel #1C1C1E (existing surface); foreground #F5F5F7 (existing ink); secondary #AEAEB2 (readable tool labels); action #D2A46E (existing owner-configurable accent); frame paper #FFFFFF (actual default drawing paper). The six values have distinct roles. Pigment colors are document content, not UI colors. Checkerboard is neutral and adjustable. Image rendering never inherits opacity, color filters or glass tint from the app window.

## Typography and geometry

Titles and Latin UI: existing Instrument Sans Variable. Arabic: bundled IBM Plex Sans Arabic. Measurements: IBM Plex Mono with tabular numerals. Drawing UI 13.5px Latin and 15.5px Arabic, Arabic leading 1.7 and zero letter spacing. Inspector headings 16px; compact utility labels 12.5px. Tool targets 40px, minimum interactive target 32px in dense inspector rows; keyboard focus uses the existing focus ring. Panel width 280px, resizable 240-420px; tool rail 52px. Controls use existing radii 8px and 14px, not new large floating capsules. Inspector language follows Worlds; document text direction is independent.

## Signature

An annotation remains attached to an image region and can open the exact linked Worlds task; the frame navigator shows the same regions used by export and presentation. These are real document relationships, visible in the editor, not illustrations or fake dashboard data.

## Layout and states

Resource header above a fixed tool row and working area. Tool rail on the reading-start edge; collapsible inspector on reading-end edge. Main canvas remains neutral. Footer reports zoom, dimensions and actual persistence status. At narrow widths the inspector becomes a dismissible sheet, not an overlay hiding permanently inaccessible canvas controls. Empty, loading, denied, broken attachment, conflict, failed-save and offline states are first-class states. Focus mode hides secondary controls. Frame artwork is never mirrored when UI direction changes.

## Motion, materials and icons

Direct pointer drawing follows input without UI easing. Tool state feedback uses inherited hover timing; camera movement is user-driven. Presentation camera motion respects reduced motion. Dark mode is justified by photo/drawing work and existing app appearance. Existing shell materials can be reused by the resource header; new drawing controls are opaque neutral tool surfaces, with no decorative glass, glow, gradients or floating navigation. Reuse the existing product paintbrush icon for the resource. New tool icons use concrete tool geometry, accessible names and consistent optical size. No characters are introduced; any future character assets must come from Doti.

Brush-size support remains 1-2048. A paint-work limit counts each spray particle and textured pigment primitive instead of silently reducing the selected size or dropping persisted samples. When a live gesture reaches its bound, one explicit localized message asks the user to release, save the painted portion and start another stroke. Escape still cancels the gesture. The existing neutral canvas and brush controls remain; no new decoration is added. Streaming is internal to the renderer. Current cross-surface antialiasing differences remain a visual acceptance issue and must not be called resolved from exact replay on matching tiles.

Library insertion, applying a saved brush/palette/style and creating a drawing from a library template follow the editable-project export rule. Their existing buttons stay unavailable during permission checks and explain refusal or offer retry after a failed check. Creating from a template is one native operation; a refused or failed copy must not leave a blank destination page. Checking a copy never holds the UI database mutex during networking. A legitimately created independent copy keeps its own originals after source access is removed. These controls use existing text, buttons and status roles; no new panel theme is introduced.

Uniform marker/highlighter pigment follows original pointer samples in one viewport path, preserving a flat chisel endpoint or a round marker endpoint. Pressure changes width through the stored curve; taper uses traveled document distance. Overlapping pieces form one opaque geometric union before applying the stroke's color alpha, opacity and constant flow, so crossing a stroke never darkens it. Separate strokes still accumulate. This makes the existing pressure-size and flow controls meaningful for these pens. Pressure-opacity/pressure-flow controls are not applicable to a uniform highlighter and must be treated explicitly when the advanced brush panel is completed. Original samples stay unchanged.

Transformed raster strokes composite canonical 512px tiles on one viewport-sized surface before applying stroke opacity, erasing or alpha-lock semantics. Adjacent edge texels come from the original neighboring tile, not repainted pigment. GPU quads have consistent pixel ownership and a real texel halo; the Canvas fallback partitions integer device pixels and samples continuous source mosaics. Pigment centers use a 1/256 document-pixel raster grid while original hardware samples remain unchanged. Crayon/pencil temporary painting surfaces add a bounded influence margin before storing the central 512px tile, avoiding clipped tiny granules. None of these renderer decisions changes the editor's visual controls or accepts the unmeasured hardware/performance gates.

The advanced brush inspector uses compact labeled slider/number pairs in the existing 280px inspector. Numeric fields allow exact 1-2048px sizes without forcing a long slider drag. Controls follow actual renderer applicability: uniform marker/highlighter omit per-dab alpha/hardness/spacing/ellipse controls; their round/chisel selector, constant flow, pressure width and taper remain available. Laser exposes width/opacity/fade duration. Fill, selection and shape controls appear only with those tools. Brush cursors show the maximum unpressured ellipse/square/scatter footprint and tip angle; peer stroke selections follow transformed ink bounds.

Image tips import an owned original and journal its asset before becoming active. The panel states that an image tip keeps its original colors. A local 24px round-pen test area reports actual pointer type/raw pressure/peak/tilt and applies the chosen pressure curve to the same test samples. It never enters artwork, history, exports or presence. Physical hardware calibration belongs to the pen driver; no hardware support is claimed from synthetic/mouse input. New controls use existing neutral tokens, numeric font and bundled Arabic typography, without additional animation or decoration.

Selection handles use eight small square grips and a round rotation grip, with a white backing and the existing selection blue so they stay visible over actual artwork. Keyboard grip edits are serialized through the current saved scene so rapid keys are not dropped while the preceding edit persists. Raster tile compositing can use one shared WebGL2 sampling surface, with Canvas 2D retaining canonical pigment generation and a Canvas fallback. Canonical pigment keeps the original rasterizer, then freezes once into CPU-readable 512px storage; cold-cache readback is bounded per tile and hot replay does not read back. Original samples and attachments remain intact. A conservative segment hierarchy skips empty subtrees without skipping dab samples or changing deterministic noise. Canonical and mip pixels share a 128MiB LRU, spatial indices have an 8MiB LRU and shared GPU textures have a separate 128MiB LRU. These are cache budgets, not claims about total-process memory.
