# Portable editable drawing projects

R13.10 supports an optional rendered preview, operation history and independent editable experiments in `.worldsdraw` files. Existing scene-only files remain version 1. History requires version 2; editable experiments require version 3 so older readers cannot silently discard branches.

Each experiment contains its editable scene, original comparison base, description, status and pinned presentation snapshots. Import creates a new local main project and separate editable experiment pages linked to that new source. It preserves the original comparison even when the exported main drawing has changed since the experiment began. Branch snapshots receive independent IDs and owned original files; comparison aliases still refer to the corresponding imported main snapshots. Imported operation IDs, toggles, restores and snapshot references are remapped. Original operation authors and `requiresBase` guards remain intact. Imported library publication metadata is stripped.

The native importer creates a nonce-bound archived stage with no parent, workspace or shared sync state. Raw original files are uploaded through the existing binary attachment command. The final document, comparison bases and editable branches install in one SQLite transaction, then become visible. It rejects changed, shared, existing, wrong-owner and wrong-nonce targets. Failure or cancellation removes the stage and its unreferenced owned files. Cancellation is disabled during the final atomic commit. Replacing the current drawing imports only its main scene and required presentation pins, as one normal editable operation; retaining experiments or history requires the new local project path.

Export includes every branch and comparison snapshot in the source authorization context. Independent experiment page IDs are supplied separately, even for text-only branches without attachment owners. Their own project export policy is checked before packing and again by the native writer immediately before saving. Other source and attachment access checks continue to apply. Source-page metadata and imported author IDs never grant access.

Limits: 24 experiments, 500 operation-history entries, 500 presentation snapshots, 64 MiB native editable installation and export authorization context, 512 MiB compressed or decompressed package, and 256 MiB original bytes during export. Preview images are static verified PNGs at most 320 by 180 pixels. SHA-256 verifies and deduplicates original bytes. No base64 originals cross the final native install IPC.

## Evidence

- `npx vitest run src/drawing/packageExperiments.test.ts src/drawing/package.test.ts src/drawing/portableHistory.test.ts`: 15 passing tests, including branch/base/pin remapping, source-policy denial before originals, cancellation during raw import, corrupted directories, removed historical originals, history Undo and preservation of `requiresBase`.
- `cargo test --lib drawing_package::tests -- --nocapture`: 6 passing entries, including an isolated child process. It verifies editable branch operations and process reopen, original comparison bases, pinned aliases, atomic rollback, nonce/shared-target refusal, real byte-exact owned file copies and cancellation file cleanup.
- `qa/native-package-owned-originals.json`: receipt from the isolated native owned-file test.
- `qa/native-package-source-policy.json`: four checks through two Rust processes, actual local Worker authorization and the real binary native writer. A text-only experiment denies View when its project policy requires Full, permits Full with exact saved bytes, and denies after revocation while preserving the existing destination file.
- `qa/browser-package-experiments.json`: 10 checks from the real browser renderer and synthetic development backend. Imported main, original comparison and editable experiment have exact green, red and blue pixels. Editing and Undo affect only the independent experiment. Preview/history and cancellation also pass.
- `qa/browser-pair-export.json`: 8 checks for the existing clean/annotated ZIP export. It verifies exact PNG pixels and CRCs, both filenames, cancellation, missing-frame refusal and source preservation.
- `npm run typecheck` and native compilation passed.

These tests use isolated data, not the installed account. Browser evidence validates the renderer and development bridge; native tests validate SQLite, ownership and policy independently. Physical second-device transfer, installed native file chooser behavior and a full native visual roundtrip are outside this evidence. Experiment histories are not included separately: their current editable scenes and comparison snapshots are included. The optional journal belongs to the main project. Failed-process staging recovery is not an automatic garbage collector; normal failure and explicit cancellation clean up the stage.
