# Drawing comment search and access

Status: design only. Global comment search and independent comment read rights are not implemented. Search inside the current drawing is limited to the comment threads already present in the authorized live session.

## Current boundary

Comments for a page share one Yjs document. The synchronization service sends that document to a client with page view access; it checks authorship and page access when changes are written. There is no stored per-thread or per-comment read policy. A search endpoint cannot add private comments safely while the existing synchronization channel still sends every comment to every page reader. The current local `pages_search` and MCP paths also query the page index without a separate online comment-rights check. Comment bodies must not be added to that index.

## Required design

1. Define an authoritative comment-read policy in the identity service, separate from edit and export rights. Specify the scopes supported by the product, the owner who can change them, inheritance, and defaults for existing comments. A denied or unavailable policy check must fail closed. Restricting a search result while sending the same hidden comment through the existing Yjs channel is insufficient.
2. Store comments with different audiences in separate authorized synchronization documents, or replace the channel with a protocol that never sends a hidden comment, its snapshots, its update history, notification excerpts, or attachment references to an unauthorized recipient. Restrict the existing all-comments channel when independent read policies are enabled. Old clients that cannot enforce the new protocol must not receive restricted comments. Migrate existing data without deleting the original until the authorized migration commits.
3. Search through an authenticated server endpoint, with no global plaintext comment index exposed through `pages_search`. For each candidate drawing, check the current identity, page membership and the independent comment-read policy before reading any corresponding comment partition. Return only permitted, nondeleted results and minimal identifiers and snippets. Bound query length, candidate count, response count, and work per request. Do not retain query text in application logs.
4. Recheck access immediately before returning results. Associate the operation with a document access epoch and reject it if a policy or membership change occurs during the operation. Notify live sessions of revocation, clear visible comment and search results, and discard or isolate any cached comment partitions that are no longer authorized. Clear results on account switch, sign-out, or a failed access check. Offline global search must fail closed rather than use stale authorization.
5. Integrate the application and MCP through the same server-side authorization contract. MCP currently runs a synchronous local SQLite search and has no trusted source for the Yjs comment document or its current independent read policy. It needs a narrowly scoped authenticated search bridge with token lifecycle and per-result access checks; it must not consume cached comment bodies or page-search snippets as a substitute. The application must similarly invalidate in-flight results on query, session, and access changes.

This design does not claim that page-level `view` or comment export permissions constitute an independent comment-read policy. Until the protocol and policy exist, keep comment search scoped to the already-loaded drawing session and leave requirement R01.08 open.
