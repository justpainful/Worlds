# Identity and presence compatibility review

## Evidence

- `services/identity/src/domain/sessions.ts` rotates refresh tokens and revokes on reuse. `WorldsIdentity` writes a refresh-in-flight marker before transmission; an interrupted request can require sign-in even if the service never consumed the token. A separate, unintegrated continuity experiment is under review and is not part of the application. Keychain entitlements, extensions, process crash and live passkeys remain unverified.
- `services/sync/src/doc.ts` sends authenticated identity before document updates, rejects client IDs owned by a different socket, overwrites user.id, and removes a socket's states at disconnect. `src/sync/provider.ts` republishes local state on reconnect and removes remote state locally. The Swift session now rejects sync or acknowledgement before identity verification, refuses unknown or revoked access levels, clears visible presence and access on disconnect, and refuses a newer non-null state claiming its own yrs client ID. This collision policy is deliberately fail-closed and is stricter than y-protocols.
- Stopping during token acquisition, document loading or socket creation now invalidates that run. A newly opened stale socket is closed; another run is refused until the previous run finishes. A failed heartbeat closes the socket to trigger reconnect. Tests covering pre-auth frames and collision are present but have not run on an Apple SDK.

## Open work and limitations

Presence and identity remain experimental and are not connected to product UI. The client does not yet implement editor RelativePosition and selection rendering, full payload/schema validation, drawing presence, access-level change propagation to editor, token expiry scheduling, or end-to-end cursor interoperation. Native collaboration has no full live crash/restart or hostile endpoint testing. It depends on TLS and the service's user and device checks; arbitrary injected transports are test-only trust boundaries. Awareness metadata and peer counts require resource bounds before exposure to untrusted servers. Yjs keeps peer clocks when remote states are removed locally: after reconnect a same-clock snapshot can remain hidden until that peer's next renewal, normally 15 seconds. Explicit invalid JSON handling is stricter and atomic per decoded update. Collisions are detected only when a conflicting update is observable; a single shared client ID across separate processes is not generally safe. No Apple compilation, Keychain, device, or local Worker result is claimed for this review.
