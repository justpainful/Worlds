# Authentication, access and collaboration trace

Scope: code inspection of the Apple worktree and its Windows/service sources. It is not a complete security audit or evidence of production runtime behavior. No credentials or real user data were used. Status maps to the Account and authentication, Collaboration and sync, and Permissions and approvals rows of `FEATURE_PARITY_MATRIX.md`. Those rows remain partial or planned until the original acceptance criteria are verified.

## Sign-in and token lifetime

- `src-tauri/src/account/commands.rs` creates a device key, sends email verification or passkey PKCE exchange, persists the account and asks `account/sync.rs` to pull account data. `account/secrets.rs` owns credential-store material; `account/client.rs` caches access tokens in memory and serializes refresh inside the process. Sign-out attempts remote logout then forgets local secrets. `services/identity/src/routes/auth.ts` enforces email challenge attempts, expiry and one-time consumption, and handles passkey and token endpoints. These statements describe source, not a completed device test.
- `services/identity/src/domain/sessions.ts` hashes refresh tokens, checks device proof where the public key exists, rotates with a compare-and-update, and revokes a session on reuse of the immediately previous token. `WorldsIdentity` reproduces Ed25519 signing and prevents replay after an uncertain rotation by persisting an in-flight marker. Its default Keychain item is not scope-specific and multiple instances are not coordinated; experimental `WorldsIdentityContinuity` scopes the item and adds only an advisory lock. Lock file replacement, shared entitlements, concurrent legacy clients, crash and cancellation require review. A keychain write failure after rotation can force sign-in again.
- Browser callback state, passkey associated domains/origins, recovery, account cache synchronization and actual deployed identity service remain unverified. The default identity URLSession rejects redirects. The collaboration WebSocket now also uses a no-redirect delegate by default; injected sessions can bypass that policy. Its unit case calls the delegate with a synthetic redirect and awaits Apple CI, and does not prove real WebSocket redirect handling.

## Local and service permissions

- Windows `account/permissions.rs` grants personal pages locally; shared pages require an active account and cached workspace membership. Owner/admin receive full, otherwise the nearest cached per-page access wins and member defaults may apply. The function intentionally returns full for missing/personal page rows, so callers must still check object existence; that behavior must not be generalized into a standalone authorization oracle.
- Identity `services/identity/src/domain/access.ts` resolves the server ACL using membership, per-user entries, nearest group entries, workspace entries, inheritance breaks and defaults. Sync `services/sync/src/access.ts` normalizes unknown levels to none and asks the identity binding. Cached local rights are not the server ACL and cannot guarantee immediate revocation. Drawing endpoints have separate access and lease checks in `services/sync/src/doc.ts`.
- Windows MCP enters through `src-tauri/src/mcp.rs` with `account::guarded_tool_call`; the tool-specific permission graph, Discord approval side effects, and complete actor provenance must be verified for each tool. The Apple chat coordinator currently passes no MCP server; it is not equivalent to Windows tool support and must not be enabled as such.

## Transport, persistence and revocation

- `src/sync/provider.ts` connects using `worlds-sync.v1`, synchronizes content and comments as separate Yjs documents, sends awareness, schedules JWT refresh and uses ping/pong. `services/sync/src/index.ts` verifies token and access before routing; `doc.ts` rechecks cached access, closes revoked sockets and applies channel-specific writes. When the identity binding is unavailable the service can continue using a cached grant for up to five minutes; this is service source behavior, not an Apple guarantee.
- `src-tauri/src/sync/mod.rs` stores snapshots, ordered updates, outbox, cursor state and rejected causal snapshots. `Apple/RustCollaboration/src/store.rs` checks the active user, page/workspace binding and cached level, and atomically appends log plus outbox. Rejected updates are archived, but complete recovery and block mirroring are not implemented. An isolated local Worker test existed in CI for earlier commits; consult the current run for results rather than inferring that later edits passed.
- Apple `CollaborationSession` verifies returned user ID and known access level before sync frames, uses state vectors and acknowledgement watermarks, and stops or archives on server rejection. Native presence and restricted plain-text insertion are experimental. Editor-relative positions, all original editing semantics, multi-process coordination, ACL refresh, attachment synchronization, automatic JWT scheduling, full lifecycle and real device/network validation remain open. Local cached permissions and initial server access do not replace server authorization at commit time.

## Priority verification still needed

1. Multi-process refresh rotation, Keychain access groups, cancellation and reboot recovery under controlled accounts.
2. Authentication redirects, URLSession WebSocket endpoint and credential handling against local controlled servers on macOS and iOS.
3. Revocation and role downgrade during in-flight writes, stale ACL caches, reconnection, outbox recovery and content preservation with two real local service clients.
4. A verified bridge from Yjs relative positions to the native editor, and exact authorization of all page, drawing, file, MCP and approval paths before enabling UI.
5. Platform signing, associated domains, passkey device origin, network failures and visual review on actual supported Apple OS versions.
