# Reader and resource parity trace

Status: focused inventory in progress, not an exhaustive repository audit. Evidence below is source inspection, not a claim that every original behavior works at runtime. The original baseline is repository commit `185ee9a`; the Windows working tree also has unrelated uncommitted drawing changes. This trace uses paths in the Apple branch for common source unless explicitly noted, and does not count the local drawing changes as committed Apple behavior. Apple feature status is separate from isolated module or test success. No row is marked Native Implementation Complete.

## Shared data paths

* Original route: `src/resources/views/ResourceView.tsx` switches on `pages[id].kind`; drawing, document, presentation, project, gallery, file, and stream each have dedicated views, while pages/templates fall back to `src/views/PageView.tsx`. `src/state/store.ts` `openPage` handles current/tab/left/right, and `src/shell/Sidebar.tsx` and `pageActions.ts` expose navigation gestures. The resource hook in `ResourceHeader.tsx` calls `api.page(id, true)`, reloads on `externalRevision`, and writes resource metadata through `api.setPageMeta`; `src/lib/api.ts` routes to Tauri commands such as `page_get`, `page_meta_set`, `page_update`, `search`, `history_list`, and attachment commands in `src-tauri/src/commands.rs`. The SQLite operations are in `src-tauri/src/store/` and `db.rs`.
* Apple route: `Apple/App/WorldsApp.swift` opens a user-selected SQLite database, loads a `WorldsDatabase.snapshot`, selects personal records and routes project/gallery/presentation/file to `ResourceContentView`, other kinds to `PageContentView`. `WorldsDatabase` filters deleted and shared/workspace rows by default, reads SQLite read-only, and requires supported schema versions; `WorldsSearch` performs local personal search and filters results against the snapshot. Shared workspace collaboration and full authorization are not implemented by this reader. `PageContentView` renders selected structured blocks without writing them; unsupported material is labeled rather than transformed. Current file-access permission, iCloud/File Provider coordination, all platform dimensions and device behavior remain to be validated.
* Tests named below identify executable tests or fixtures, **not** newly observed passes. `WorldsUITests` uses isolated bundled SQLite fixtures and screenshots; `WorldsLocalCopyUITests` and `ProjectEditorHarnessUITests` exercise separate experimental or isolated copy flows. Consult the actual Actions run and commit for their result. The harness passed a fixture path on macOS and iOS in run 42412393488; it does not prove product parity, shared access, real file-provider scopes or any untested UI state.

## Counting rules

Rows are scoped capabilities, not an exhaustive atomic feature count. A feature is complete only after equivalent behavior is integrated and verified on the required Apple targets, including permissions, relevant persistence and user-visible interactions. Isolated modules, successful compilation, screenshots and fixture tests are evidence for their specific scope only. Do not compute overall percentage from these rows while the wider parity inventory and required test matrix remain incomplete.

### Focused personal-search update

`src/shell/CommandPalette.tsx` requests up to 24 results, includes templates, presents snippets, and instantiates a selected template. The Apple sidebar asks `WorldsSearch` for up to 30 personal results; it reads rather than instantiates templates. It now labels template results as view-only to make that difference explicit. Search still lacks the original command palette, create actions, recent list and tab/split destinations, and does not refresh the entire snapshot automatically after external changes. Its SQLite implementation intentionally filters workspaces/shared metadata and private parent titles, so it is not shared-search parity. The app gives each in-flight query a request ID in addition to its query and database-generation checks, so an older same-query request cannot overwrite a newer result after a save or refresh. The isolated search fixture now includes a template, and the existing UI test checks its label. These changes await Apple CI and screenshots; no new run is claimed here.

### Experimental personal project links

The personal project draft has an optional link/unlink UI behind `WORLDS_EXPERIMENTAL_PROJECT_LINKS`, disabled until Apple validation. Its candidates are derived from the personal, nondeleted snapshot; the UI excludes the project, templates, existing links and active children, while Rust rechecks the project and each link target inside the atomic metadata compare-and-swap transaction. The view stages form changes before applying a link change, participates in existing unsaved undo/redo, and preserves unrelated metadata. Existing links that are no longer authorized can cause Rust to reject saving rather than silently remove them. The candidate snapshot can become stale, so rejection and reload remain necessary. No shared-project write, create-child action or full source-project parity is claimed.

Two isolated Swift integration tests were added for link/unlink save/reopen and for a target becoming shared before save, plus a UI test for the local-copy flow; none has yet been run on Apple. UI behavior, keyboard, VoiceOver, conflict presentation and security-scope lifecycle require Apple CI and manual visual review before enabling the flag.

### Link recovery states

The experimental editor now explains malformed or duplicate links and blocks their mutation, rather than silently removing repeated entries. If loading fails because the project or a linked page is unavailable or no longer personal, it gives a conservative message that does not reveal the target's identity and offers reload; the text warns that creating another independent copy does not carry across edits in this one. Reload before an editing session opens does not ask to discard a nonexistent draft. No automatic repair, bypass of permissions or removal of a missing link is implemented; returning to the original project and restoring access or correcting its links may be necessary. SwiftUI tests use isolated fixtures for a duplicate link and a missing link and assert the warning/reload or preservation behavior. These additions await Apple CI and accessibility/visual verification.
