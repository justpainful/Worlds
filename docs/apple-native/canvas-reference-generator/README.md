# Canvas reference provenance

The transparent PNG fixtures are generated by `DrawingRenderer.render` from the original `src/drawing/renderer.ts` using headless Chrome 156.0.8078.81, the Canvas backend, disabled viewport cache and no background. `index.html` builds the original scene with the production drawing model and renderer, and `entry.ts` exposes these to the page. A bundler plugin redirected only `../lib/api` to `api-stub.ts`; no attachment, worker or external service is used by these cases. Source hashes at capture: renderer `0122360296B81C162E73119DA76B3C756E0DDBAC453A7350DAE1D7B315CFF150`, brush `AE4C823909E09D0237FEC077A18E818646DBCE856458426DB54BD8EA02230D55`.

The 15 references include 64 and 256 pixel canvases, pressure, taper, alpha, source-over layers, handwriting and highlighter presets. The pressure-sensitive highlighter reference is recorded as unsupported by the native candidate; it is never treated as a successful comparison. The hard, ink and pencil source cases with identical settings are not distinct pigment algorithms; additional preset cases exercise different settings.

The Apple comparison reports premultiplied sRGB RGBA mean absolute error over the entire image and separately over the union of pixels whose source or candidate alpha exceeds 4/255. It also reports the maximum channel error and count of painted pixels with a channel difference greater than 2/255. Both source and native PNGs are attached for visual inspection. The 0.02 painted-region threshold is a diagnostic guard, not proof of parity. Differences at antialiased edges, orientation, color space and canvas scaling need individual review. Tests are required to fail on threshold violations and must retain reports even on failure.

No Apple results are asserted in this document. The renderer is not wired to the product, and its support excludes pressure-sensitive highlighter, soft or textured dabs, erasure and many layer effects.

The initial CoreGraphics comparison used the generic CGColor convenience initializer. Extracted opaque pixels showed a color mismatch even where alpha matched, so the test now constructs the same numeric channels in the explicit sRGB color space used by CSS. This is a correction to comparison inputs, not proof that remaining antialiasing or pressure differences are fixed. A fresh Apple run is required.

The `right-triangle-4x.png` reference uses the same production renderer, Canvas backend, transparent background, and 4x viewport scale. It contains three explicit points, a 3px round-joined `#202023` outline and no fill. Reproduce from the repository root with esbuild and playwright-core installed under the temporary `worlds-reference-tools` prefix, then run `node docs/apple-native/canvas-reference-generator/generate-right-triangle.cjs`. The bundled worker URLs are unused in this shape case. The native comparison remains unverified until Apple CI runs.
