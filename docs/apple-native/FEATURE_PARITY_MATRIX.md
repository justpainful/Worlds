# Apple native feature parity matrix

Status: inventory in progress. This is not yet an exhaustive audit and source inspection is not runtime verification. The Apple application and core have partial implementations; no complete end-to-end feature is claimed.

Source inspected: local Windows working tree at commit `185ee9a1019c8b7bc685d22dabf1b699579189cc` plus its pre-existing uncommitted changes. The Apple branch starts at that commit and does not contain those uncommitted changes. In particular, drawing and screen annotation include local modifications and untracked files; parity must be assessed against both versions without publishing private data or overwriting the Windows workspace.

Status below refers to the Apple port. `Planned but Not Implemented` does not assert the source feature is fully working. `Blocked with Documented Reason` identifies a technical dependency needing a compatible implementation, not permission to omit the feature. Tests listed are required acceptance tests, not results.

## Unknowns and audit gates

- The rows above group systems, not an exhaustive inventory of individual behaviors. The denominator for a completion percentage is not established.
- Dependency declarations alone do not prove a user-facing feature. In particular CAD and 3D require traced implementation before inclusion as existing features.
- Inspect source files and data paths not yet covered, current tests and known issues, all native commands and service contracts, and the original's modified and untracked implementation before locking the matrix.
- No row is marked `Existing and Verified` because no source feature has been verified end to end in this audit. No row is `Native Implementation Complete`.
- Source-specific limitations such as unsupported drawing effects must be verified separately and must not be represented as completed native parity.
