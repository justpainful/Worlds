# Native resource summaries

The native app routes personal snapshot pages with kind `project`, `gallery`, `presentation` or `file` to a read-only SwiftUI summary. Project metadata and links come from the page JSON; link buttons select only pages already present in the personal snapshot. Child pages are listed by parent ID, excluding archived pages and templates. Gallery names and captions and presentation text and notes come directly from stored blocks. File name, MIME type and size come from file metadata. Unsupported or malformed content is marked as unavailable. Slide geometry, images, video, rich layout, resource editing, sharing and export are not implemented.

No database writes or shared-resource permission checks are added. The summary inherits the limitations of the existing personal snapshot filtering and does not make it an authorization system. The UI fixture contains only synthetic data, including an attachment reference that is never dereferenced. Added UI tests require Apple execution and visual review. Do not interpret these summaries as full resource parity.

Linked IDs absent from the filtered snapshot are identified as unavailable without exposing their titles. Duplicate link IDs are shown once. Slide numbering counts slide blocks rather than unsupported blocks. Gallery labels and file metadata come from the containing page and do not establish that an attachment exists or is authorized. The snapshot currently excludes explicit shared flags but its treatment of malformed sync metadata is narrower than RustStore personal-write checks; this requires a separate fail-closed review before treating it as an authorization boundary.

An experimental personal-file metadata query and isolated file access test exist, but preview is not wired to the app. The query checks page ownership and metadata in a SQLite snapshot; a separate vault checks file paths and rejects multiple hard links. SQLite authorization and filesystem open are separate operations, so ownership may change between them. The vault does not protect all ancestor replacement races, provide file-provider coordination or enforce live revocation. Sharing remains disabled by default. Apple integration tests and security review are required before wiring these pieces into the product.

Project facts use a compact horizontal layout when it fits, and stack at narrow or accessibility sizes. Project navigation rows use larger hit targets. These changes and RTL behavior await new Apple visual review.
