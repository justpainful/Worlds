# Experimental native table row

Worlds uses Tiptap TableKit and exposes adding rows and columns and toggling header rows in `src/editor/PageEditor.tsx`. The personal-copy editor experiment adds an explicitly named **Add row at end** action for a selected root table in a document. It appends empty cells without moving existing rows or rewriting their content. The action accepts only rectangular tables with at most 99 existing rows and 32 columns, no merged cells or non-default column widths, and an ordinary-cell final row. Unsupported cases are refused. Undo, checked baseline saves and conflict handling use the existing editor pipeline.

This is not a full table editor or a replacement for Add Row Below, column editing, header toggling, merged cells, width editing, visual grid selection, collaborative editing or the original spreadsheet behavior. Existing opaque content stays in place and is still checked by persistence. New unit, isolated SQLite and UI tests have not yet run on Apple; accessibility, text direction, empty-cell input and visual layout require device or simulator verification. The local editor remains experimental.

The experiment also offers **Add column at end** for rectangular unmerged root tables of at most 100 rows and 31 existing columns. It appends a plain cell to each row and uses the last cell's header/body type, without moving existing cells. Unsupported spans, column widths and cell attributes cause rejection before mutation. This does not implement the original Add Column Right at the selection and remains subject to Apple UI and interoperability testing.

**Insert row below** now supports a restricted selected-row case. It rejects merged or irregular tables and refuses the operation if any following row contains attributes, marks or nodes whose protected positions would shift. The inserted cell types follow the pinned `prosemirror-tables` 1.8.5 rule for the selected header/body boundary. This is still narrower than the original: common default cell attributes in a later row cause conservative rejection. Apple and interoperability tests remain required.

**Insert column after selection** follows the selected-column header rule from `prosemirror-tables` 1.8.5 for the supported unmerged rectangular subset. Before inserting, it rejects cells to the right whose attributes, marks or unknown nodes have position-sensitive protection. It does not implement merged-cell expansion or guarantee insertion through default attributes in shifted cells. Model, isolated SQLite and UI tests are present but await Apple execution.

**Delete selected last row** requires an explicit confirmation. It refuses the sole remaining row, any non-final selected row, merged or irregular tables, and a row with unknown attributes, marks, node shapes or other protected content. The confirmed deletion is undoable in the editing session and uses the checked save transaction. It is not a general replacement for the original table deletion commands. Newly added model, SQLite and UI tests await Apple execution.

**Delete selected last column** requires explicit confirmation and refuses the only column, non-final selections, merged or irregular tables, and removed cells with unsupported attributes, marks or node shapes. The edit supports session undo and checked saves. It does not implement general column deletion. Model, isolated SQLite and UI tests await Apple execution.
