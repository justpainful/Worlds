# Collaborative editor binding: review and isolated primitive

Worlds stores editor content in Yjs XmlFragment `default`, using y-prosemirror node elements, attributes, and formatted XmlText. `src/sync/mirror.ts` translates the fragment and folds block changes against their prior Yjs state. `src/sync/extensions.ts` uses a Yjs binding and rejects unauthorized local edits while applying remote edits. `WorldsNativeEditor` instead edits a projected JSON tree and its personal persistence bridge rejects shared pages. Replacing the full shared tree or saving it through that personal bridge would overwrite concurrent work or bypass the current data model.

`Apple/RustCollaboration/src/editor.rs` provides an isolated Rust-only primitive: it rebuilds a private replica from an exact Yjs state, checks a single plain XmlText and expected text, validates UTF-16 positions including surrogate boundaries, rejects styled or embedded text and structural edits, and generates a Yjs update against that base. It does not mutate the live document or persist anything. It checks that its randomly generated client ID does not already occur in the base state. Two synthetic concurrent clients on a genuine Yjs fixture converge in local Rust tests. This does not prove compatibility for all Yjs nodes, editing, rendering, permission checks, Swift or network interoperation.

A safe binding still needs a stable node identity rather than an array position, full conversion of every original node and mark without loss, Yjs relative selections, IME coordination, granular CRDT changes with durable transactional outbox before exposing success, concurrent remote changes, access changes and disconnect handling, shared block mirror/history compatibility, undo origin tracking, and comprehensive real-service and Apple device tests. Checking the prior text alone cannot detect replacement of a block by a different block with identical text. This primitive does not enforce authorization, bind to a live session, solve collision coordination across independent writers, or expose FFI. It must not be used by the product editor. The native editor and shared collaboration session remain disconnected until those conditions are satisfied.

The isolated storage bridge now identifies exactly one top-level `bid`, compares the full reconstructed CRDT state within an immediate SQLite transaction, rechecks cached account and page write rights, and commits the generated update to both log and outbox before returning it through C and Swift. Changed state returns a conflict; an outbox insertion failure rolls back the log. Rust fixtures cover stale competing edits, failed insertion, reopen, access downgrade and the C boundary. The Swift fixture is written but has not run. This path is not called by the session or editor: calling it without first coordinating the in-memory document and live access would leave the replica stale. Cached authorization is not a substitute for server authorization. The current byte comparison is intentionally conservative, and UTF-16 plain-text insertion is the only supported operation.
