The Worlds MCP server

Worlds comes with an MCP server that lets Claude Code, or any other program that speaks MCP, read and edit your pages on your computer, with the same safe tools the in-app assistant uses. A version is saved before every write, and every write can be undone.

What it is

MCP is a standard way for AI programs to connect to tools. The Worlds server is the Worlds app itself running in a special mode: worlds.exe --mcp. It talks to the program over standard input and output on your computer and opens the local Worlds database directly. Nothing goes over the internet or through Worlds servers.

The server is available in the Windows app.

Connecting Claude Code

From inside Worlds (easiest)

  1. Open Settings, Claude

    In the Claude Code group there is a row, "Use Worlds from Claude Code sessions".

  2. Click Register

    Worlds adds its tool server to your Claude Code user configuration. You see "Worlds tools registered with Claude Code". The button is off if Worlds cannot find Claude Code on the PC.

  3. Start a new Claude Code session

    Now "Your Claude Code sessions can read and edit pages through the same safe tools." The Integrations view shows "Also available in your Claude Code sessions".

If you move or reinstall Worlds, click Register again.

With the command

This is the command the Register button runs. The path is where Worlds usually installs on Windows. If you installed it somewhere else, use the path to your worlds.exe:

claude mcp add --scope user worlds -- "%LOCALAPPDATA%\Worlds\worlds.exe" --mcp --actor ai

--scope user makes the tools available in all your projects. --actor ai records changes as made by AI in the Worlds history, so you can tell who changed what.

Other MCP clients

Any program that runs a local MCP server over standard input and output needs a command and arguments:

Command
%LOCALAPPDATA%\Worlds\worlds.exe (or your install path)
Arguments
--mcp --actor ai
Type
stdio

In the format most programs use:

{
  "mcpServers": {
    "worlds": {
      "type": "stdio",
      "command": "C:\\Users\\YOU\\AppData\\Local\\Worlds\\worlds.exe",
      "args": ["--mcp", "--actor", "ai"]
    }
  }
}

Codex inside Worlds (from Settings, Providers) gets the Worlds tools automatically. Worlds has no button that registers the server with the Codex you use outside the app, so add it with the command and arguments above.

Which workspace it uses

The server opens the Worlds database on your computer: %APPDATA%\Worlds\worlds.db. If the WORLDS_DATA_DIR environment variable is set, it uses that folder instead. The Worlds app sees changes the server makes and refreshes open pages.

  • Planning and study: planning_list, planning_create and planning_update for the items of the Study pack: subjects, classes, exams, assignments, things to bring, tasks, lessons and goals. planning_create makes up to 200 items in one request, such as a subject with its weekly classes.

Safety and undo

  • Every write is recorded with who made it, and the changes of one session are grouped together.
  • Before the first change to a page, Worlds saves a version of it.
  • history_undo reverts everything changed in one operation, and versions_restore restores a version and keeps the current state as a version too.
  • In the app: open the page, then its History panel, and click Undo next to the group of changes. See History and versions.
  • The tools work on Worlds pages only. They give the program no access to the files on your computer and no shell.

Discord sends wait for your approval

discord_send, discord_edit and automations_run send nothing. They put the request in Needs approval in the Worlds Activity view, and the server replies that nothing was sent and the request waits for your approval. An automation that a program creates through MCP is always saved to wait for approval before each send. To approve, the Worlds app must be open. See The approval queue.
